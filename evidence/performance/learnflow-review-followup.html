무엇을 바꿨나

작성자 일괄 조회 이후에도 수강 정보를 리뷰마다 지연 조회하고 있었습니다. 리뷰와 연결된 단일 수강 정보를 함께 가져오도록 @EntityGraph(attributePaths = "enrollment")를 적용했습니다. 작성자 조회 방식과 응답 형식은 유지했습니다.

변경 전후 비교

시간은 회차별 평균 3개의 중앙값. SQL은 별도 진단 실행의 요청당 횟수입니다.

측정 조건

데이터합성 강의 100개, 강의당 리뷰 100개, 전체 리뷰 10,000개
요청강의 100개를 순회하며 첫 페이지 조회. 생성 시각 내림차순
환경Apple M4 Pro, macOS 26.6.2, Java 17.0.18, MySQL 8.4.11
반복변형별 3회. 각 페이지 크기별 워밍업 200회 후 300회 측정
통제같은 기준 커밋과 엔티티 생성 스키마. 매 실행마다 새 JVM과 MySQL 컨테이너. 후보만 EntityGraph 적용
측정 구간읽기 트랜잭션, 서비스와 DB 처리, 응답 객체 생성. HTTP와 동시 부하 제외. 시간 측정 중 SQL 및 호출 스택 수집 비활성화

응답과 페이지 경계 검증

전후 동일성강의 3개 × 페이지 크기 2종, 6개 조합의 응답 전체 및 총건수 일치
기능 검사30개 조합에서 공개 리뷰 ID, 정렬, 총건수를 독립 SQL과 대조. 작성자 닉네임과 강의 제목 확인
예외 조건숨김 리뷰 제외, 빈 페이지, 마지막 페이지, 존재하지 않는 강의의 기존 예외 확인
