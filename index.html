    강의 승인을 기다리게 하지 않는 AI 요약 작업 처리

    문제
    승인된 강의의 영상으로 AI 요약을 생성해야 했습니다. 승인 요청 안에서 분석까지 실행하면 관리자가 분석이 끝날 때까지 기다려야 하고, 승인 후 분석 서버를 별도로 호출하는 방식은 호출에 실패했을 때 처리할 작업이 기록되지 않을 수 있었습니다.
    해결 방안 검토
    강의 승인 시점에는 ‘분석해야 할 작업’을 빠짐없이 기록하고, 시간이 오래 걸리는 분석은 별도로 실행하도록 나눴습니다. 이를 위해 승인 정보와 작업 기록을 같은 DB에 함께 저장하는 Outbox 방식을 적용했습니다.
    해결·개선
    강의 승인과 영상별 분석 작업 등록을 하나의 트랜잭션으로 묶고, 분석 서버가 대기 중인 작업을 가져가 결과를 전달하는 API를 구현했습니다. 작업은 대기, 처리 중, 완료, 실패 상태로 관리하고 같은 영상의 작업이 중복 등록되지 않도록 제한했습니다.

    분석 서버가 실패를 알린 작업은 1분, 5분, 60분 뒤에 다시 가져갈 수 있도록 최대 3회의 재시도 기준을 마련했습니다. 그 결과 승인 처리가 분석 완료를 기다리지 않으며, 작업의 진행 상태와 재처리 대상을 DB 기록으로 구분할 수 있게 했습니다.

    AI 처리 단계 안내와 생성 실패 시 대체 결과 제공

    문제
    음성으로 일기를 만들려면 음성 인식, 감정 분석, 일기와 위로 문구 생성을 차례로 거쳐야 했습니다. 단순히 ‘처리 중’이라는 상태만 제공하면 사용자는 어느 단계가 진행되고 있는지 알기 어려웠습니다. 일부 생성 과정에서 오류가 발생하더라도 이미 인식한 내용은 활용할 필요가 있었습니다.
    해결 방안 검토
    작업 접수와 AI 실행을 분리하고, 접수된 일기 ID로 현재 처리 단계를 조회하도록 구성했습니다. 생성 단계의 오류는 기존에 확보한 내용이나 기본 문구로 대체할 수 있도록 처리했습니다.
    해결·개선
    업로드된 음성과 일기 정보를 저장한 뒤 HTTP 202 응답과 일기 ID를 먼저 반환하고, BackgroundTasks로 AI 처리를 이어갔습니다. 음성 인식, 감정 분석, 일기 생성 등 단계가 바뀔 때마다 진행 안내를 DB에 기록해 조회할 수 있도록 했습니다.

    일기 본문 생성 중 예외가 발생하면 음성에서 인식한 원문을 사용하고, 제목과 위로 문구는 각각 본문 첫 줄과 기본 문구로 대체했습니다. 이를 통해 사용자는 처리 단계를 확인할 수 있고, 일부 생성 과정에 실패하더라도 확보한 내용을 활용한 결과를 받을 수 있도록 했습니다.

    녹음 음량 차이를 보정하는 음성 입력 처리

    문제
    사용자가 녹음한 파일은 음량과 형식이 서로 달랐습니다. 기존에는 파일 형식을 변환했지만 음량 차이는 별도로 보정하지 않아, 작게 녹음된 음성도 그대로 인식 모델에 전달하는 구조였습니다.
    해결 방안 검토
    인식 모델을 변경하는 것과 함께, 모델에 전달하기 전 녹음 상태를 정리할 필요가 있었습니다. 기존의 파일 형식 변환을 유지하면서 음량 정규화를 추가하고 인식 설정을 조정했습니다.
    해결·개선
    기존 16kHz 모노 WAV 변환 과정에 음량 정규화를 추가해, 입력 파일의 음량을 보정한 뒤 인식하도록 했습니다. 인식 모델을 small에서 medium으로 변경하고, 이전 구간의 인식 결과를 다음 구간에 조건으로 사용하는 옵션을 껐습니다.

    그 결과 파일 형식뿐 아니라 음량을 함께 정리하는 전처리 흐름을 마련했습니다.

    대표 감정 하나만 집계하던 통계 개선

    문제
    한 일기에서 여러 감정의 점수를 분석했지만, 통계에는 가장 높은 감정 하나만 집계했습니다. 기쁨과 슬픔이 함께 분석된 일기도 대표 감정 한 건으로만 반영돼, 나머지 감정 점수는 통계에서 빠졌습니다.
    해결 방안 검토
    대표 감정별 일기 수를 세는 대신, 각 일기에 저장된 감정별 점수를 누적하도록 집계 기준을 바꿨습니다. 사용자 리포트와 운영 대시보드에도 같은 기준을 적용했습니다.
    해결·개선
    처리가 완료된 일기의 감정별 점수를 합산하고, 집계 값이 없는 감정은 0으로 표시하도록 변경했습니다. 리포트 API와 운영 대시보드의 지표도 동일한 점수 누적 방식으로 맞췄습니다.

    그 결과 대표 감정에 가려졌던 다른 감정의 분석 점수를 통계에 함께 반영하고, 두 화면이 같은 기준으로 감정 분포를 보여주도록 개선했습니다.
